## How this was reviewed

The diff was split into 11 chunks (phase_1 ×2, the Motorola-8 tables, decode.c, stack/parse, linker core, linker listfile+debug, the new CPU tables, the assembler core, the auxiliary tools, and a non-C breadth sweep). Each chunk was reviewed against the working tree (full surrounding context, not just diff text), with instruction encodings cross-checked against the respective ISAs. Every high-severity finding below was then **reproduced on freshly built binaries** — those carry a ✅ **VERIFIED** marker with the exact bytes/exit code.

**All 182 regression tests pass at HEAD.** That is the problem, not the reassurance: several of the bugs below are *certified* by the test suite (the expected `@BT` bytes encode the wrong answer), and most new features have no byte-asserting test at all (see the [coverage matrix](#test-coverage-matrix)).

## 🔴 Critical — silent wrong code generation (v10.7 regressions)

<a id="c1"></a>
### C1. eZ80 FD-page index↔index loads encode the wrong register — `iez80.c:550, 584, 612, 613`

```c
550:  { "LD IX,(IYs)", 0x37fd, 4, 0, 0 },
584:  { "LD IY,(IYs)", 0x31fd, 4, 0, 0 },
612:  { "LD (IYs),IX", 0x3ffd, 4, 0, 0 },
613:  { "LD (IYs),IY", 0x3efd, 4, 0, 0 },
```

On the eZ80, the second opcode byte under an `FD` prefix selects IX at `0x31`/`0x3E` and IY at `0x37`/`0x3F` — the **inverse** of the ED/DD pages. The table extrapolated the DD-page mapping to the FD page.

✅ **VERIFIED** (`wla-ez80` + `wlalink`):

| Source | Emitted | Actually executes | Correct |
|---|---|---|---|
| `ld ix,(iy+1)` | `FD 37 01` | `ld iy,(iy+1)` | `FD 31 01` |
| `ld iy,(iy+1)` | `FD 31 01` | `ld ix,(iy+1)` | `FD 37 01` |
| `ld (iy+1),ix` | `FD 3F 01` | `ld (iy+1),iy` | `FD 3E 01` |
| `ld (iy+1),iy` | `FD 3E 01` | `ld (iy+1),ix` | `FD 3F 01` |
| `ld ix,(ix+1)` | `DD 37 01` | *(correct)* | `DD 37 01` |

Cross-checked against CEmu (hardware-validated TI-84 CE core: opcode `0x31` under a prefix writes `index[PREFIX ^ 1]`) and binutils' eZ80 assembler. **The bug is baked into the project's own tests** — `tests/ez80/instructions_test/main.s:120,123` and `tests/ez80/all_instructions_test/main.s:626,660,688,689,2192,2211,2225,2226` assert the wrong bytes, so the regression suite certifies the defect.

**Fix:** swap the hex pairwise — `LD IX,(IYs)`→`0x31fd`, `LD IY,(IYs)`→`0x37fd`, `LD (IYs),IX`→`0x3efd`, `LD (IYs),IY`→`0x3ffd` — and correct the ten `@BT` expectations.

<a id="c2"></a>
### C2. 68000: labels/defines named `S0`–`S7` silently assemble as register A7 — `decode.c:969` (+5 sites)

The new `SP`-for-`A7` alias (CHANGELOG: "[68k] Added alias SP for register a7") widened the register-parse condition but failed to gate the *digit* disjunct to A/D:

```c
if (c == 'A' || c == 'D' || c == 'S') {                                   /* :969 */
  ...
  if ((code[i] >= '0' && code[i] <= '7') || (c == 'S' && toupper((int)code[i]) == 'P')) {
    if (c == 'S')
      *reg1 = 7;                                                          /* :976 */
```

For token `S3`: `c=='S'` enters, `'3'` satisfies the first disjunct, and `c=='S'` forces `*reg1 = 7` → parsed as A7. In v10.6 `c=='S'` failed `(c=='A'||c=='D')` and the token fell through to label/number parsing.

✅ **VERIFIED**: `S3: move.w S3,d0` assembles to `30 0F` = `MOVE.W A7,D0` (mode 001/reg 111), where the correct encoding for the absolute label `S3` is `30 38 00 00` (`MOVE.W $0000.w,D0`). Any v10.6 source with a label, `.EQU`, or `.DEFINE` named `S0`…`S7` now reads register A7 instead — silent wrong code, no error.

The same un-gated disjunct is replicated at **`decode.c:1035` (`(An)`), `1100` (`(d16,An,Xn)`), `1295` (`d16(An)`), `1347` and `1373`** (`_mc68000_parse_register`). `SP`, `SR` (`:829`) and the register-list `SP` entry (`:845`, which correctly requires `code[i+1]=='P'`) are fine.

**Fix** at all six sites: `((c == 'A' || c == 'D') && code[i] >= '0' && code[i] <= '7') || (c == 'S' && toupper((int)code[i]) == 'P')`, keeping `*reg1 = 7` only on the SP arm.

<a id="c3"></a>
### C3. Section-relative labels passed to `.MACRO` resolve to the section start — `stack.c:4062`

The flagship v10.7 feature ("A label … inside FORCE or OVERWRITE .SECTION given to a .MACRO can now be used in calculations") computes the wrong address for any label at non-zero offset:

```c
s->type = STACK_ITEM_TYPE_VALUE;
s->value = g_slots[section->slot].address + section->address;   /* :4062  — section start! */
```

The outside-section branch (`:4045`) correctly uses `dSI->address`. Here `dSI->address` (the label's actual in-slot address, set from `s_dsp_add` at `:5975`) is discarded in favour of the section's base.

✅ **VERIFIED** (agent repro, `wla-gb`): a FORCE section at `ORG $10` with `First:` (offset 0) and `Second:` (offset 1) passed through `.MACRO … ARGS lbl` / `.PRINTV lbl+0` prints `16`/`16`; correct is `16`/`17`. Silent wrong code.

**Fix:** `s->value = g_slots[section->slot].address + dSI->address;`

<a id="c4"></a>
### C4. `.#b`/`.#w` size hint miscomputes parenthesized low-precedence expressions — `stack.c:2309-2333`

The new size-hint operator rewrites only the *single previous* infix item into `( item & mask )`. When the previous item is the `)` of a parenthesised sub-expression, the rewrite wraps only the `)`, and because `&` (priority 50) binds tighter than `|`,`^`,`==`,`&&`,… the mask attaches to the wrong operand.

✅ **VERIFIED** (agent repro): `.PRINTV ($131|$0F).#b` prints **319** (`$13F`, i.e. `$131 | ($0F & $FF)`) instead of **63** (`$3F`). Control `$131.#b` → `49` (correct). Wrong with `|`,`^`,`&&`,`||`,`==` inside the parens; `+`,`*`,`<<` happen to work (priority > 50). Silent wrong value.

**Fix:** when `si[q-1]` is `SI_OP_RIGHT`, walk back to the matching `SI_OP_LEFT` and insert the wrapping group there; or append `& mask` via a dedicated high-priority mask op instead of injecting a broken `LEFT/RIGHT` pair.

## 🟠 High — crash / hang / OOB / silent linked-output change

<a id="h1"></a>
### H1. `mid()` signed-overflow → unbounded heap write → SIGSEGV — `stack.c:1478`

```c
if (start + length > string_length) { ...error... }   /* :1478 — start+length overflows int */
...
for (i = 0; i < length; i++)
  si->string[i] = tmp[start + i];                      /* :1486 — writes 'length' bytes */
```

`start` and `length` are user-supplied (`g_parsed_int`). `mid(1, 2147483647, "abc")` → `1 + INT_MAX` wraps to `INT_MIN` (signed-overflow UB), the guard passes, and the loop writes ~2 GB into the 256-byte `si->string`.

✅ **VERIFIED**: `.PRINTV mid(1, 2147483647, "abc")` → **`Segmentation fault (core dumped)`, exit 139**. `left()`/`right()` escape only by accident (`start==0`, or `start` goes negative first).

**Fix:** test `length > string_length - start` (operands already validated non-negative and bounded), or clamp `length` to `string_length` before the addition.

<a id="h2"></a>
### H2. `.REPT`/`.REPEAT` option parser infinite-loops on any unexpected trailing token — `phase_1.c:10880`

The new `START`/`STEP` option loop (`_directive_rept_repeat_while`) only exits on `INPUT_NUMBER_EOL`. Any other token after the count is rolled back and re-tested forever:

```c
while (1) {
  if (compare_next_token("INDEX") == SUCCEEDED) { ...; continue; }
  else if (compare_next_token("START") == SUCCEEDED) { ...; continue; }
  else if (compare_next_token("STEP")  == SUCCEEDED) { ...; continue; }
  _remember_current_source_file_position();
  q = input_number();
  if (q == INPUT_NUMBER_EOL) { ...; break; }
  else _roll_back_to_remembered_source_file_position();   /* re-tests identical input → spin */
}
```

✅ **VERIFIED**: `.REPT 2 5` → **hang, killed by `timeout` (exit 124)**, no output. With `q == FAILED` it also re-prints the same parse error unboundedly. This additionally removes v10.6's tolerance for same-line `.REPT` bodies (now a hang instead of a defined behaviour).

**Fix:** in the `else`, after roll-back, `print_error(ERROR_DIR, ".%s has an unexpected token after the count.\n", c); return FAILED;` (or accept-and-ignore to restore v10.6 tolerance).

<a id="h3"></a>
### H3. `.FAIL` multi-string concatenation off-by-one OOB write — `phase_1.c:13540`

```c
char s[1024];
...
else if (q == INPUT_NUMBER_STRING || q == INPUT_NUMBER_ADDRESS_LABEL) {
  if ((int)strlen(s) + (int)strlen(g_label) < (int)sizeof(s)+1)   /* allows == 1024 */
    strcat(s, g_label);
```

The guard `< sizeof(s)+1` permits `strlen(s)+strlen(g_label) == 1024`, but `strcat` then needs 1025 bytes — the NUL lands at `s[1024]`, one past the buffer. `MAX_NAME_LENGTH` is up to 2047 (`shared.h`), so a single argument can be that long. Trigger: `.FAIL "<512 chars>" "<512 chars>"`. Stack OOB write from assembler source; with stack protectors it converts a clean `.FAIL` into an abort. (Source confirmed; the changed guard is the off-by-one.)

**Fix:** `< (int)sizeof(s)` and error on overflow instead of silently dropping the argument.

<a id="h4"></a>
### H4. Macro string-argument substitution overflows a 1 KB static buffer — `phase_1.c:1172`

```c
static char s_replacement_memory[1024], s_replacement_backup[1024];   /* :257 */
...
strcpy(&s_replacement_memory[i], ma->string);   /* :1172 — no bound check */
i += (int)strlen(ma->string);
```

`_run_macro_replacements()` substitutes string-typed `\N` arguments into a macro-body line via this 1024-byte static scratch buffer. `ma->string` is `MAX_NAME_LENGTH+1` (up to 2048). The outer `while (i < 1024)` is checked only at the top of each iteration; the `strcpy` inside writes `strlen+1` bytes unconditionally. This is reachable through the new "quoted string arguments in .MACROs" feature: a >1 KB string argument referenced on a macro body line overflows into adjacent file-scope statics. The escaped-quote (`:1113`) and newline (`:1187`) branches have the same "check once, write several" shape. (Source confirmed.)

**Fix:** bound every write — before the copy, `if (i + (int)strlen(ma->string) + 2 >= (int)sizeof(s_replacement_memory)) { print_error(...); return FAILED; }` and re-check `i` before the multi-byte quote/newline writes.

<a id="h5"></a>
### H5. LATESTDIR/RELATIVEDIR path construction has three unbounded concatenations — `phase_1.c:4896`, `include.c:88`

The new include-directory machinery concatenates a directory and a path with no length check:

```c
void use_dir(char *directory, char *path) {        /* phase_1.c:4896 */
  char tmp[MAX_NAME_LENGTH + 1];
  strcpy(tmp, directory);
  strcpy(&tmp[(int)strlen(tmp)], path);             /* dir+path can be ~2×MAX_NAME_LENGTH */
  strcpy(path, tmp);                                /* overflows caller's buffer too */
}
```

`directory` (`g_latest_include_dir`, up to `MAX_NAME_LENGTH`) + `path` (up to `MAX_NAME_LENGTH`) can total ~4094 chars, overflowing the local `tmp` and then the caller's `path[MAX_NAME_LENGTH+1]`. `get_dir()` (`phase_1.c:4906`) has the same flaw. Independently, `_try_open_file()` in `include.c:88` copies the directory part of the dynamically-sized `g_full_name` into the fixed `g_latest_include_dir[MAX_NAME_LENGTH+1]` with an unchecked loop — this needs **no** LATESTDIR usage, just a long `-I` directory. Triggered by long `-I` roots + nested includes.

**Fix:** length-check `strlen(directory)+strlen(path)` and clamp `len` to `MAX_NAME_LENGTH`, emitting the existing "file name length" error.

<a id="h6"></a>
### H6. `wlalink` silently flipped duplicate-label resolution (last-wins → first-wins) — `wlalink/write.c:2338`

In v10.6 `_try_put_label` always ran `hashmap_put` after the duplicate warning; since `_hashmap_hash` returns the existing element on a key match, the **last** duplicate inserted won all lookups. v10.7 returns early:

```c
/* don't insert duplicates into the hashmap */
return SUCCEEDED;                                   /* :2338 — first definition now wins */
```

So under `-c` (the explicit "allow duplicate labels with differing values" mode after the `-c`/`-C` split), every reference now resolves to a *different* instance than v10.6, and the per-duplicate warning is gone. **Linked output changes across the version bump with no diagnostic.** (Source confirmed.)

**Fix:** if last-wins is intended, restore the unconditional `hashmap_put` on the `g_allow_duplicate_labels_and_definitions == YES` path; if first-wins is the new intent, document it in the CHANGELOG and emit a warning.

<a id="h7"></a>
### H7. Cx4 register parser uses `atoi`, accepting garbage identifiers as registers — `decode.c:424`

```c
if (label[0] == 'R' || label[0] == 'r') {
  value = atoi(label + 1);            /* :478 — ignores trailing non-digits */
  if (value < 0 || value > 15) return FAILED;
  *reg = 0x60 + value;
  return SUCCEEDED;
}
```

`atoi("abbit")==0`, so `Rabbit`→R0, `R2D2`→R2, `IRQfoo`→IR0. Called from the Cx4 operand parser, so `MOV A,Rabbit` (where `Rabbit` is a user define expected to fall through to the immediate path) silently emits `MOV A,R0`. The sibling `_cx4_looks_like_register_name` does this correctly with `isdigit`.

**Fix:** require the suffix to be 1–2 all-digit characters before accepting R/IR.

## 🟡 Medium — broken new features, dead flags, off-spec output

<a id="m1"></a>
### M1. `-MG` and `-MD` makefile flags are provably no-ops; `-MG` is also inverted — `main.c:536, 573`

```c
else if (!strcmp(flags[count], "-MG"))  g_makefile_skip_file_handling = NO;   /* help: "Enable fake file handling" */
else if (!strcmp(flags[count], "-MD"))  g_test_mode = OFF;                    /* help: "Request .o generation" */
...
if (g_makefile_rules == YES && g_makefile_rule_file == stdout) {   /* runs after the flag loop */
  g_test_mode = ON;  g_makefile_skip_file_handling = YES;          /* clobbers both */
}
```

`g_makefile_rule_file` is initialised to `stdout` (`main.c:1113`). Both flags assign their variable's existing default, and the post-loop block then overrides them. `-MG` sets `NO` while its help text says "Enable" (inverted), and `wla -M -MD file.s` still writes no `.o`. Also a behaviour change vs v10.6: `-M -MF deps.mk` now performs a full real assembly instead of a dry run. (Source confirmed.)

**Fix:** `-MG` → `YES`; track `mg_given`/`md_given` and let the stdout block fill only unset values (the existing `test_given` pattern).

<a id="m2"></a>
### M2. Link-time `.ASSERT` before the first `.SECTION` aborts library builds — `phase_3.c` (OUTPUT_LIBRARY first loop)

`_directive_assert` always emits the `~` token with no section requirement. The OBJECT-mode and shared loops gained a `case '~':` skip, but the **OUTPUT_LIBRARY** first loop (cases `' ' E j I t S f k`) was missed, so a top-level `.ASSERT cond LDERROR "msg"` in a library source falls into the default case: *"INTERNAL_PHASE_1: A section must be open …"*.

**Fix:** add `case '~': fscanf(g_file_out_ptr, "%d ", &inz); continue;` to the library first loop.

<a id="m3"></a>
### M3. Deferred `.ASSERT` containing `~` (NOT) always errors at link time — `wlalink/analyze.c:308`, `write.c:4493`

`_read_assertions` forces assertion stacks to `STACK_TYPE_UNKNOWN`; `compute_stack`'s `SI_OP_NOT` handler enumerates only sized types and otherwise fails *"COMPUTE_STACK: NOT cannot determine the output size"*. So any link-time assert using `~`, e.g. `.ASSERT (~flags & $80) == 0`, aborts the link.

**Fix:** in the `SI_OP_NOT` handler, treat `STACK_TYPE_UNKNOWN` as 32-bit, or assign assertion stacks a defined width when read.

<a id="m4"></a>
### M4. Section `BASE` leaks out of the section when no prior `.BASE` was set — `stack.c:5609`

Section-open backs up `s_dsp_base` unconditionally but restores only when the backup was `>= 0`:

```c
/* 'S' */ s_dsp_base_backup = s_dsp_base; if (s_dsp_s->base >= 0) s_dsp_base = s_dsp_s->base;
/* 's' */ if (s_dsp_base_backup >= 0) { s_dsp_base = s_dsp_base_backup; ... }   /* :5609 */
```

With no `.BASE` active before a `.SECTION … BASE $80`, the backup is the `-1` sentinel, the restore is skipped, and `$80` sticks — every later label gets `base = $80`, skewing `base()` and `bankbyte()` in `.IF`s. ✅ agent-verified (`base(After)==$80` true for a label defined after the section). Contradicts the CHANGELOG ("The old .BASE … is returned after .ENDS").

**Fix:** restore unconditionally — `-1` is itself a valid state to restore.

<a id="m5"></a>
### M5. `get_next_token()` now expands string `.DEFINE`s globally → keyword-collision hazard — `parse.c:1740`

The #641 fix ("BANKS can be a string definition") substitutes any token matching a string define at the *end of every* `get_next_token()` call, which has 30+ call sites parsing directive keywords. `.DEFINE BANK "3"` followed by `.SECTION "x" BANK 1` now silently rewrites the `BANK` keyword before matching — mis-parsing the directive with no diagnostic pointing at the cause.

**Fix:** gate the substitution to the call sites that want it (a flag like the existing `{}`-expansion gate).

<a id="m6"></a>
### M6–M9. New debug-export (`-E`) formats are off-spec — `wlalink/dbgexp.c`

The brand-new `-E <emulator>` exporter is internally sound (allocation discipline, JSON escaping all checked) but several emitted formats won't load in the tools they name:

- **M6 `dbgexp.c:184` — "mesen" emits FCEUX `.nl` syntax, not Mesen `.mlb`.** Writes `$ADDR#LABEL#` to a `.msn` file; Mesen needs `MemType:Offset:Label` in `.mlb`, FCEUX needs per-bank `<rom>.nes.#.nl`. Neither loads it.
- **M7 `dbgexp.c:12` — breakpoint labels exported with empty names.** `_is_label_exportable()` accepts `LABEL_STATUS_BREAKPOINT`, which have empty names by construction, so `-E vice` emits `al 0040 .` etc. (invalid). Drop breakpoints from the name-based writers.
- **M8 `dbgexp.c:161` — `no$sns` produces non-SNES `bank:addr`.** Uses the RGBDS-like `(bank+base)&0xff` path; SNES needs the LoROM/HiROM PC-bank mapping that `write_symbol_file()` already special-cases. Truncates banks > 255.
- **M9 `dbgexp.c:207` — `.sld` is not SLD format.** Writes `name = $xxxx` (a z88dk `.map`); CSpect's SLD loader expects pipe-delimited `|SLD.data.version|` records and rejects this.

Additionally (Low) the RGBDS/BGB/SameBoy/Emulicious extensions (`.rgb`/`.emu`) are not what those emulators auto-load (`<rom>.sym`), so output needs a manual rename to be usable.

**Fix:** emit each format to its real spec/extension, or document `-E` as "WLA's own dump format" rather than per-emulator.

## ⚪ Pre-existing (surfaced by the diff, **not** v10.7 regressions)

These were verified to exist unchanged in v10.6 — fix opportunistically, but they don't gate the release.

- **`i6801.c:300/303` — `LSL x,X` emits illegal opcode `0x65` (should be `0x68`).** ✅ VERIFIED (`wla-6801`: `lsl 5,x` → `65 05`, `asl 5,x` → `68 05`; LSL≡ASL so both should be `68`). Both lines were *touched* by the reorder, so the moment to fix was missed. `0x65` is unassigned on the 6801 — arguably worse than a wrong-but-valid opcode.
- **`i6809.c` (12 sites) — 16-bit-register immediates (`LDX #`, `CMPD #`, `LDD #`…) encoded as 1-byte type 1.** `LDX #$1234` won't assemble; `LDX #$1A` silently emits the 2-byte form. Blessed by `tests/6809/all_instructions_test` — a deliberate-looking but hardware-incorrect design.
- **`byte_tester/main.c:723/757` — signed-`char` comparison** makes `-n` (not-found) tests with high-bit strings vacuously pass (silent) and `-y` tests with such strings always fail (loud). Fix: `(unsigned char)tmp[j]`.
- **`byte_tester/main.c:819` — a testsfile truncated before `END`** still executes the partial byte list and can exit 0 in `-a` mode.
- **`phase_1.c:11457` (SNES native/emu vector handlers)** print an uninitialised 512-byte stack buffer when a field is given a float; byte-identical to v10.6 (only moved).
- **`wlalink/write.c:3585` — `[addr-to-line mapping v2]` reads with stride 3 but data is stored with stride 5** (in-bounds but wrong fields); and `wlalink/listfile.c:998` leaks `listfileitems_ptr` on fatal internal-error paths. Both unchanged from v10.6; the new dbgmodel path does the mapping correctly.

## Adjudicated verdicts

<a id="verdict-the-4--wmaybe-uninitialized-warnings"></a>
### Verdict: the 4 `-Wmaybe-uninitialized` warnings (decode.c:2119/2140/2159/2174) — **benign**

All four are SH-2 `IMM8*` modes calling `_sh2_emit_low8(..., value, result_type, ...)`. `_sh2_parse_number` writes `*value` only for `result == SUCCEEDED`/`INPUT_NUMBER_STACK`; for the `INPUT_NUMBER_ADDRESS_LABEL`/EOL/STRING/FLOAT cases it leaves `value` unset. But `_sh2_emit_low8` *reads* `value` only under `result_type == SUCCEEDED`/`INPUT_NUMBER_STACK` — exactly the cases where it was written. GCC can't track the `value`↔`result_type` correlation across the call boundary. No reachable wrong-codegen or crash. **One-line silencer:** `*value = 0;` at the top of `_sh2_parse_number` (`decode.c:1581`).

<a id="verdict-718"></a>
### Verdict: the #718 `.L` fix (`8e55b088`, decode.c:4115) — **correct, minimal, complete for 65816**

The fix adds, in the W65816 16-bit `'?'` handler, `if (g_operand_hint == HINT_24BIT && g_operand_hint_type == HINT_TYPE_GIVEN) break;`. Instructions with no long form have `skip_xbit == 0` on their abs16 entry (e.g. `LDX |?` at `i65816.c:400`), so pre-fix `LDX foo.l` sailed past the older `HINT_24BIT && skip_xbit == 1` guard and silently dropped the `.l`. Post-fix it breaks and the user gets a proper error. It **cannot** reject valid 24-bit instructions: 65816 long addressing uses the separate `'&'` case (`LDA &`, type 3), which the new `break` correctly falls through to; eZ80 `.LIL`/`.SIL` are driven by mnemonic suffixes, not operand hints, and weren't touched. Residual (note, not regression): the same explicit-`.l` drop still exists in the other 65xx blocks (6502/65C02/65CE02/HuC6280 — which have no 24-bit forms anyway) and in the 65816 immediate (`case 4`) and 8-bit (`case 0xA`) handlers. Diagnostic gaps, not wrong bytes.

<a id="verdict-objfmt"></a>
### Verdict: object/library file-format write/read symmetry — **OK**

The new records (link-time `.ASSERT` block, `REFERENCE_TYPE_DIRECT_8BIT_MAX_BITS` extra byte, SH-2/Cx4 stream tokens `W K H a l m @ ? ! ~`) were checked field-by-field between the assembler writer (`phase_4.c`) and the linker reader (`wlalink/analyze.c`) for both OBJECT (`include_slot_bank_base=YES`) and LIBRARY (`NO`) variants — no desync. The format version is correctly bumped (`WLAl`→`WLAm`, `WLAI`→`WLAJ`), so stale v10.6 objects are rejected by `check_file_types`/`check.c` before the new readers run.

<a id="verdict-bytetester"></a>
### Verdict: byte_tester exit-code contract — **SOUND**

A byte mismatch sets `failures = 1` → `_main_run` returns 1 → `main` returns 1. In `run_tests.sh`, `runTest()` re-runs `set -e` as its first statement inside the `OUT=$(runTest …)` subshell, so a nonzero `eval "$BYTE_TESTER testsfile"` aborts before the trailing `make clean` could mask it. The function-local `set -e` is **load-bearing** — without it `make clean`'s status would overwrite the failure. The v10.7 rewrite is a net *hardening* (fixes stale-address leakage between tag tests, OOB reads on <3-byte files, `%255s` token splitting, unchecked overflow in number parsing).

## Recommended fix order

1. **Codegen correctness (tag-blockers):** C1 (eZ80 FD-page + fix the 10 test expectations), C2 (68000 S-label, 6 sites), C3 (section-label address), C4 (`.#b` grouping). Add the regression tests the suite currently lacks or mis-asserts.
2. **Crash/hang/OOB (tag-blockers):** H1 (`mid` overflow), H2 (`.REPT` hang), H3 (`.FAIL`), H4 (macro string buffer), H5 (LATESTDIR concat ×3).
3. **Silent linker behaviour:** H6 (`-c` last-vs-first-wins — decide + document + warn), H7 (Cx4 `atoi`).
4. **Broken features / dead flags:** M1 (`-MG/-MD`), M2 (library `.ASSERT`), M3 (deferred `~`), M4 (BASE leak), M5 (`get_next_token` substitution), M6–M9 (`-E` formats).
5. **Low/minor + pre-existing:** sweep opportunistically; the `WLAVALRGIND` typo and the missing `i6800` `DEC/TST` and eZ80 `LEA` entries are cheap, high-value cleanups.
